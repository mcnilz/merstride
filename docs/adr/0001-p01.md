# P01 implementation decisions

Accepted on 2026-11-15. The user approved the baseline and P01–P07 slices.

Use one production project with namespace boundaries, source-generated System.Text.Json,
and YamlDotNet low-level parsing. P01 accepts only a single end node; other syntax
fails explicitly until its owning slice. End success and failure share the same path.
Persist the compiled snapshot and source hash, never recompile during advance.
Use OS-exclusive per-run file handles and same-directory atomic replacement.

Test seams are the public CLI and public compiler/policy commands specified by the user.
Use NUnit 4 and the official Cucumber Gherkin AST parser with explicit step bindings.
Expand outline rows independently, and select P01 when either feature or scenario owns it.
Later cases are reported as not implemented. Invalid YAML is tested at the CLI seam
without claiming the entire P04 validation outline.

Use local tickets and leave work uncommitted. Review the working tree against initial
commit project initialization, including untracked additions.
Release automation and full analyzer-distribution evidence remain P07.

Development workflow policy checks reuse the restored YamlDotNet assembly to inspect
YAML values rather than relying on line formatting. Required checks may not ignore
failures; the P01 aggregate gate is validated explicitly. Fork evidence is local
policy validation, with actual hosted execution unavailable. Windows Job accounting
externally observes CLI descendants; network absence is supported by code review
and a forbidden System.Net namespace rule, without claiming packet tracing.
