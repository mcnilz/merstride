# P02 process execution decisions

P01 acceptance unblocks the approved P02 ticket. Preserve the existing single
production project and public CLI/build test seams. Application coordinates the
sequential cursor through persistence and process ports; Infrastructure uses BCL
process APIs and raw streams. No shell wrapper, runtime dependency, or model call.

Compile the supported explicit graph and process/end metadata into the frozen run
definition. Persist each executing activation before launch; persist its closed-log
result and selected route before continuing. A terminal advance has no effects.
An unfinished executing activation cannot replay automatically. Full interruption,
recovery commands, crash windows, and platform qualification remain P06 work.

P02 includes basic timeout, combined output retention, and transition limits because
unbounded subprocesses would make this slice unsafe. P05 still owns the full exact
boundary and context acceptance suite. Timeout/output-limit termination is best
effort; detached descendants are outside the guarantee. No full process-tree suite
is claimed here.

Expose the latest activation in compact status and bounded log tails through the
public logs command. Keep authoritative raw bytes separate from protocol output.
Logs decode UTF-8 with replacement and omit an initial partial character when cut.
P03 adds selected context; P02 does not implement agent nodes or handoffs.

This unreleased development snapshot changes the persisted definition shape. P01
state files are rejected as corrupt rather than migrated or replayed. Start a new
run for P02; no released-state compatibility promise exists yet.

The controlled test helper is another .NET Native AOT executable, test-only and
published separately from the product. Its lock file reuses already reviewed SDK
toolchain packages. Windows Job accounting still counts every descendant: inspection
and start calls require no child, process advances require their declared children.
