# P04 authoring decisions

The approved P04 slice completes compilation at the existing public CLI seam.
Use YamlDotNet events with explicit YAML 1.2 core scalar classification, not object
construction. Decimal, octal and hexadecimal integer spellings resolve before
bounded schema validation; dates and numeric-looking nonnumbers remain strings.
YamlDotNet 18 marks are already 1-based; map them back to Markdown accordingly.

Index all executable metadata and marked diagrams by case-sensitive workflow ID.
Reject missing/duplicate/conflicting pairs across the document before selection.
Parse YAML and validate root shape/IDs for every metadata block, then apply the full
node/graph schema to the selected pair. An unselected workflow is never executed.
Ordinary blocks are ignored. Respect enclosing backtick and tilde fences; only
column-one backtick fences can introduce executable blocks. Document and selected
graph limits apply at compilation, before creating state or launching actions.

The official Mermaid 12.3.0 renderer exposed ambiguities in the contract's general
whitespace/ID wording. The exact spaced forms `done ["Finish"]` and
`done[ "Finish" ]` fail upstream parsing. Interpret the explicitly specified
declaration `id["Label"]` as a contiguous token form. Accept leading/trailing
indentation, multiple spaces/tabs between `flowchart` and `TD`/`LR`, and whitespace
between edge tokens; preserve label contents. This reconciles the explicit subset
with renderability, while the broad phrase "outside labels ... whitespace is
insignificant" could otherwise suggest unsupported token insertion.

The lowercase node IDs `end`, `subgraph`, `style`, `class`, `flowchart`, `graph`, and `interpolate`
also fail upstream parsing despite matching the ID pattern. Reject them with a
located diagnostic to preserve the ordinary-Mermaid renderability requirement.
The coordinator accepted this interpretation under delegated authority: the ID
pattern is a necessary lexical condition, not permission to use reserved keywords
that cannot form the documented declaration. This significant specification wording
tension and the exact renderer probes remain recorded; the accepted baseline is
unchanged. Workflow IDs may still use these words.

The development-only official renderer is isolated under tools/mermaid with its
own exact npm lock and reviewed inventory. Use Node and an installed headless
browser only during development verification; never ship them or invoke them from
the product. Use official Mermaid parse AND render to SVG, including entities,
cycles, both orientations, comments and all repository workflow examples. Verify
the incompatibility probes as expected upstream rejections. No renderer, JS engine,
new runtime dependency, or new production namespace dependency is introduced.

The frozen definition/source hash behavior from P02 remains authoritative. Source
changes do not recompile an existing run; workspace scripts remain live. P05/P06
retain ownership of exact runtime limits, interruptions, concurrency and recovery.
