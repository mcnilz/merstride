# Use .NET 11 Native AOT and stable C# 15 after P04

Accepted by the human on 2026-11-15 after P04: implement the project with .NET 11,
using the installed global csharp-15 skill for language support without placing
the skill in this repository. This supersedes the initial .NET 10 technology choice
only; MIT, deterministic sequential CLI execution, Mermaid/YAML ownership, existing
agent tasks and the accepted product slices remain unchanged. M01 gates P05.

Pin SDK 11.0.100 with roll-forward disabled and target net11.0 across product,
acceptance tests and native helpers. net11.0 selects stable C# 15 by default; do not
enable latest, preview or the experimental memory-safety rules. A proportional
migration keeps the established implementation and dependencies; one graph-validator
collection expression uses C# 15 constructor arguments to retain ordinal comparison.

Microsoft's official [release metadata](https://builds.dotnet.microsoft.com/dotnet/release-metadata/11.0/releases.json)
records SDK 11.0.100/runtime 11.0.0 released 2026-11-10. The installed stable SDK was
used; no installer or skill files were added. [C# 15 documentation](https://learn.microsoft.com/en-us/dotnet/csharp/whats-new/csharp-15)
confirms the language default. Reviewed Microsoft compiler/linker packages move to
11.0.0; historical .NET 10 reviews and measurements remain available.

.NET 11 [adds nine Microsoft.Extensions assemblies to the base framework](https://learn.microsoft.com/en-us/dotnet/core/compatibility/extensions/11/extensions-in-shared-framework).
NsDepCop initially rejected these implicit SDK references with NSDEPCOP07. Allow
those nine exact assembly names, as with the existing SDK reference-pack exceptions;
do not allow Microsoft.Extensions namespaces or a wildcard assembly family. Retain
the build-only analyzer reference, namespace rules and both error diagnostics.
This accommodates framework references without adopting hosting/DI/logging packages.

Repeat native CLI/build policy regressions, inspect publish inputs for analyzer
separation, and remeasure size/startup/process execution. Local Windows results do
not qualify Linux, a clean no-runtime target or hosted GitHub execution. The skill
remains an external development resource; its contents are not a product dependency.
