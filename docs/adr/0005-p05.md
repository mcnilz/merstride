# P05 exact boundary qualification

P05 keeps the accepted .NET 11 Native AOT/C# 15 implementation and public native
CLI/build seams. The existing runtime already enforces the specified boundaries;
this slice qualifies them through actual 04-limits scenarios and supplemental
boundary pairs rather than introducing duplicate policy or new runtime machinery.

Timeout evidence uses a native attached child, readiness markers and an observation
release barrier. The test holds OS process handles while both helpers are alive,
then verifies both exit after the timeout. Windows Job accounting independently
counts the CLI and its two descendants. Concurrent output uses two synchronized
writers; retention and observed totals are checked separately. Detached descendants,
user interruption, crash/recovery and cross-platform qualification are not inferred.

Expected JSON sizes use explicit compact fixture text, UTF-8 widths and the public
context envelope. Root depth is one; nested arrays and objects are qualified. No
production parser, serializer metadata or sizing helper calculates expected limits.
The 32 KiB pair includes the context envelope, not just its selected value. Invalid
byte replacement is tested after decoding because it can expand the text's size.

No dependency, product source, persisted schema, feature prose, analyzer rule or
workflow action changes are required. Review the uncommitted tree against accepted
M01 commit M01 migration; coordinator acceptance and commit
remain separate. P06 owns recovery and concurrency; P07 owns release qualification.
