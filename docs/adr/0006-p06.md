# P06 recovery and concurrent snapshots

P06 uses the accepted public native CLI/process/filesystem boundary. No private
persistence hook, fault-injection interface, runtime dependency or event store is
introduced. The per-run OS-backed writer lock covers the complete advance chain,
completion and explicit resolution. Lock-file existence does not imply ownership.

Status reads a complete saved snapshot. If executing, it probes the OS writer lock;
after acquiring it, status rereads before projecting interruption. It writes no
state. A writer records interruption; advance never replays uncertain work.
Explicit retry returns ready without execution and preserves the interrupted
activation; a later advance assigns a new ID. Explicit fail performs no actions.
Only interrupted runs can resolve. Unfinished executing state must identify an
actual process activation; structurally corrupt state is refused without reset.

Authoritative state and completion receipts remain in one JSON file. Writes flush
same-directory temporary files and use file replacement for existing snapshots;
the initial write uses rename. Readers allow delete sharing to retain their opened
snapshot while replacement proceeds. Real concurrent Windows tests exposed rename
access denial and transient sharing/missing-name windows during ReplaceFile.
Snapshot opens retry those Windows errors for at most 100 ms; parsing failures
are never retried, and persistent absence remains an I/O error. Logs never decide
execution or recovery. Physical disk failure is outside these guarantees.

Console cancellation flows from the CLI through the engine and process adapter.
It attempts attached-tree termination, drains bounded output, saves interrupted,
and exits 130. Tests send real Windows CTRL_BREAK_EVENT from a test-only hidden
private console. The two attached helpers ignore the signal, so termination must
come from the engine's process-tree attempt. The harness's extra conhost process
is independently identified in Windows Job membership and counted explicitly.
No visible helper windows, detached-tree or Linux interruption claim is implied.

If interrupted-state persistence fails, the CLI still returns interrupted and exit
130. A read-only authoritative-file fixture qualifies that refusal through the
public filesystem boundary: persisted executing bytes survive, allowing fresh
status to detect the lost writer. It neither injects a private persistence fault
nor claims physical disk failure qualification.

Crash fixtures write an external effect and readiness marker, then wait behind a
barrier. Tests kill only the engine, retain helper process handles, inspect fresh
public behavior, and clean up only identified task-owned processes. Concurrent
readers race a twelve-process chain and validate each cursor/status/transition
against explicit committed combinations. No precise before-launch or post-exit
fault window, clean-machine qualification or release workflow belongs to P06.
