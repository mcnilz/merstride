# P07 native distribution and qualification

P07 keeps .NET SDK 11.0.100, net11.0/default stable C# 15, MIT and the accepted
public native CLI/build seams. No parser redesign or CLI library belongs here;
P08 owns that explicitly approved follow-up. The global C# skill stays external.

Inspection scenarios preserve all state/log bytes, use external child observation,
and exercise explicit state roots from a fresh working directory. Product version
comes from generated assembly informational metadata, so the tested tag version
is the version returned by the native CLI and frozen into new runs.

Windows and Linux use separate checkouts/intermediates, RID-specific native outputs
and separate Linux NuGet lock files. Linux qualification uses real SIGINT directed
to the engine; attached helpers ignore it and must be terminated by the engine.
Windows retains the private-console Ctrl+Break harness. Linux execve observation
uses external strace, including resumed syscalls, while /proc identifies live
descendants. Windows Job accounting is unchanged. Linux persistence refusal removes
directory write permission because a read-only file alone does not forbid Unix
atomic replacement. No physical disk or detached-child guarantee is added.

Actual compiler/source/reference, ILC, linker and publish item sets are captured
by opt-in build targets, and resolved assets are traversed for the analyzer and
its dependency closure. NsDepCop stays build-only; audit rejects its implementation
in product inputs or contents. Runtime distribution includes YamlDotNet's MIT
notice and Microsoft's complete Native AOT third-party notices, plus .NET's MIT
license and a separate shipped-component inventory. GPL analyzer inventory stays
in development documentation. Native contents alone are insufficient proof.

Release scripts validate strict SemVer, exact tag commit on origin/main, a clean
same-run local-gate record, embedded version, platform binary hashes, archive names,
regular-file contents, Linux executable permission, complete notices, checksums,
raw qualification scenario identities and feature hashes, and twenty actual
same-agent/model experiment samples. Official same-run artifacts flow through an
always-running aggregate gate and a separate read-only verification job. Only
the final publish job receives contents:write and GH_TOKEN. Official gh creates
a draft, verifies uploaded/downloaded bytes, then publishes. Existing public
versions or mismatched drafts fail; matching drafts resume without clobbering.

Local release tests use disposable Git repositories and a controlled gh boundary.
Their simulated native bytes and qualification samples prove release control
behavior only; they are never native/platform or token-benefit evidence. No real
tag/release/remote was created. The working branch remains master; origin/main,
GitHub hosting, protected authorized tags and branch rules are external prerequisites.

Local implementation acceptance differs from release readiness. The local suite
executes 97 cases; the two clean-platform scenarios orchestrate independent
82-case runtime suites, excluding 15 separately mandatory build-only cases,
and are run separately, fail explicitly when evidence is unavailable, and
remain required. Their absence cannot create a successful release qualification.
The versioned qualification example is incomplete and publication fails closed.
Actual raw qualification arrives as external repository-variable data, separately
for each platform and experiment, avoiding a commit-SHA self-reference. Verify
embeds it in the immutable same-run bundle; publish validates that bundled copy.
A real minimal Linux chroot smoke contains only native candidates and OS libraries,
with no .NET installation; it does not claim a clean full-suite target. Windows
Sandbox/VM and the same-agent twenty-run experiment remain external evidence needs.

The official Action releases and tag-to-commit SHAs were reverified 2026-11-15
through upstream GitHub APIs/git refs. All four use Node 24, supported by the
selected windows-2025 and ubuntu-24.04 hosted-runner labels. Hosted execution and
image identities must still be recorded by an actual run; local policy is static
evidence, not a claim of a successful hosted pipeline.
