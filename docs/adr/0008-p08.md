# P08 established CLI parsing and offline discovery

The user approved P08 immediately after locally accepted P07. Keep .NET 11 Native
AOT/default stable C# 15, MIT, protocol version 1, explicit existing-agent tasks and
the accepted CLI/build test seams. No engine, persistence or workflow redesign.

Adopt Microsoft's System.CommandLine 3.0.0, verified as the current stable package
on [NuGet](https://www.nuget.org/packages/System.CommandLine/3.0.0) on 2026-11-15.
Microsoft's [overview](https://learn.microsoft.com/en-us/dotnet/standard/commandline/)
documents established .NET CLI usage and trim/AOT support. The installed official
NuGet package's nuspec identifies Microsoft, MIT and VMR source commit
`297acf930fb0f5c07fd4e51d78e521b4ad2e5d1f`; the selected net10.0 assembly has no
dependencies. Its netstandard2.0 System.Memory dependency is not selected by
net11.0. NuGet is the version authority here: the separate upstream GitHub release
page still displays 2.0.2. Package hash and selected graph are locked per RID and
recorded in dependency-inventory.json; retain the complete MIT notice in archives.

Use the library's command/argument/option model, exact arities, required options,
parse results and built-in help action. A small Cli adapter translates parsed
values to the existing execution entry point and protocol errors. Do not add a
framework, hosting/DI, reflection binding, completion service or custom general
parser. Duplicate rejection uses the parser's identifier occurrence count,
including booleans and help aliases. A narrow lexical guard requires `=` for
dash-prefixed string values: otherwise the library consumes an option-like token
as a missing value. This preserves predictable missing/unknown-option refusal.

Global output/storage options are recursive. Disable response-file expansion,
directives and POSIX bundling to avoid implicit file reads and surprise behavior.
The library consumes `--` and literal positional paths; the native test harness
has a raw-argument invocation path so it never appends globals after a delimiter.
Do not invoke parser default error/version output: errors go through protocol
JSON, and `--version` shares the existing version response. English UI culture is
set before constructing parser symbols; tests run child processes with German
locale settings. No AOT/trimming warnings are suppressed.

Help is plain English by default and a protocol object with a `guide` string under
`--json`. This explicit P08 addition preserves the one-object stdout rule and
leaves operational/version output unchanged. Help bypasses required operational
arguments/options, but rejects malformed/duplicate input. Generate/capture help
before constructing storage or opening workflow files; version likewise returns
before evaluating the state path. Append shared conventions, PowerShell examples
and exit-code guidance to library-generated command-specific help.

Keep System.CommandLine types out of all non-Cli namespaces. Explicit NsDepCop
disallows override their BCL `System.*` allows; real positive/negative compilation
fixtures prove enforcement, and the architecture gate requires all four rules.
Shipped notices/inventory and distribution/archive checks include the new package.
Clean-target identities/counts derive from the actual expanded feature inventory;
there is no P08 waiver of unfinished P07 qualification. Final Windows/Linux local
gate and native budget evidence is recorded separately in STATUS.md.

P13 supersedes the original output default above: all commands, discovery and
errors use readable text unless explicit --json selects the existing protocol.
Parser rules, global placement, malformed/duplicate-option handling and command
semantics remain unchanged. See ADR 0010 for the presentation boundary and streams.
