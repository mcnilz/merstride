# P12 inline scripts and platform variants

Keep direct process execution and its literal arguments unchanged. Add script
and variants to the existing process node, retaining timeout at node level.
Platform conditions are sets over windows/macos/linux, and are validated for
overlap across all platforms. An omitted condition is universal, not fallback.
Reject ambiguity instead of introducing precedence, expressions or order-based
selection. Missing coverage is a runtime spawn_error; this keeps workflow routing
and CLI exit codes stable and allows authors to handle unavailable execution.

Compilation owns literal-block/shebang syntax and records parsed executable,
literal arguments and script body in the frozen definition. Infrastructure owns
current-platform selection, PATH resolution and stdin transport. Neither requires
a new package, runtime shell, parser dependency across layers or provisioning.
Old direct-only run definitions deserialize using optional defaults; no migration
or reinterpretation of their args occurs. The JSON protocol remains version 1.

Use an explicit stdin execution convention, not per-interpreter heuristics or an
allowlist. Arbitrary installed executables can accept stdin, but authors must
supply the appropriate flags. Bash/Python can read stdin; PowerShell must request
-Command -. The constrained shebang tokenizer supports quoted paths/arguments,
literal backslashes and env NAME / env -S NAME ARG..., without running env or
inheriting its shell-like split/expansion rules. Unsupported env forms fail before
state creation. No implicit flags, file transport or interpreter substitution.

Missing/unlaunchable interpreter and no applicable variant retain spawn_error,
with a bounded stable diagnostic in the activation's stderr log. Existing direct
launch failure logs remain unchanged. Execution remains behind persist-before-
launch and the existing writer lock. The bounded UTF-8 stdin feeder shares the
process lifecycle and cancellation with concurrent output drain; it cannot block
timeout, output termination or explicit interruption/recovery.

Acceptance uses only the published native CLI, OS process observation and public
filesystem effects. A native stdin probe verifies arbitrary executable selection,
literal args, UTF-8 transport and paths with spaces; real installed PowerShell,
Python and Bash exercise actual scripts. Recovery fixtures dispatch the native
test helper as an interpreter to retain deterministic barriers and real signals.
This is local platform evidence, not independent clean-target qualification.
