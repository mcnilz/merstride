# P13 readable CLI output

Keep command execution and the protocol-1 response model intact. A Cli-only output
adapter renders each existing response either with the original source-generated
JSON serializer or readable English text. It has no storage/process dependencies
beyond the existing response types and performs no workflow actions. The logs
command supplies its already parsed activation ID as text-rendering context; do
not add a JSON response field solely for a text header.

Select text by default for every command, even when redirected. Before parsing,
recognize --json and --json=... only before the literal delimiter so malformed
and duplicate options still receive protocol errors. This small output selector
does not validate or replace System.CommandLine; its parser still rejects invalid
input. Keep generated help, guides and version independent of workflow/state
access. Move the operational guide before state-path evaluation as well.

Text results go to stdout; validation diagnostics and errors go to stderr. Avoid
duplicating the same validation error from its response error/diagnostic fields.
Failed-run status keeps its successful inspection exit code while showing the
failure reason. Preserve JSON field order, values, escaping and single-object
stdout, with no text duplicated on stderr. No version increment for presentation.

Use compact labelled run/request/receipt summaries and bounded selected context.
Logs retain activation/stream/tail-truncation headers and the existing byte bound.
Render Unicode directly in UTF-8 without BOM. Normalize CRLF to LF; preserve LF
and tab; escape other control/format characters visibly. This prevents terminal
escape execution while leaving saved bytes and JSON untouched. No terminal
detection, color, table library, new dependency, storage schema or engine change.

Existing automation must request --json explicitly. Audit benchmarks, release
scripts, native helper/harness calls and the clean-Linux smoke; their JSON readers
already use the flag. Update P08's version discovery row to explicit JSON and
P11's mixed-mode guide/error assertions while preserving all requirement tags.
Dedicated P13 native cases cover both modes and actual completion/recovery/log
effects, not an internal renderer seam. Record platform evidence in STATUS.md.

P17 extends this presentation with live stderr activity after successful writes
through a CLI persistence decorator; see [ADR 0013](0013-p17.md). The original
single-response JSON renderer and the execution modules remain unchanged.
