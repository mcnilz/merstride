# P14: Complete the existing tag-based release path

Extend P07's GitHub Actions workflow and public build/release boundaries. Do not
introduce a parallel release mechanism or weaken qualification to get a release
published. Stable and prerelease tags export the version embedded in native
artifacts; build metadata is deliberately excluded from release tag syntax.
The CLI protocol version remains separate from the product's SemVer version.

All release checkouts explicitly select the event commit, preventing a moved tag
or branch default from changing the source between validation and platform builds.
The public workflow policy rejects missing or different checkout refs. Tag tests
use disposable local repositories; publication tests use the controlled GitHub CLI
boundary. Neither creates a remote tag or qualifies an actual release.

Windows x64 and Linux x64 remain the complete required release set. macOS Native
AOT is technically supported, but the existing mandatory non-Windows acceptance
path uses Linux strace and /proc. There is no verified macOS toolchain, dependency
lock/audit or clean-target evidence here. Defer macOS distribution, with osx-arm64
as the first follow-up target, until its native acceptance and complete release
qualification path are implemented. Do not silently skip a required macOS job or
advertise unverified binaries. The detailed assessment and maintainer/download
procedure are in RELEASING.md.

DailyWingetNotify's MIT-licensed release workflow was reviewed at revision
c8007fbffd9b9ea704e6c382afce5edb193ebeac. Its tag/version/prerelease conventions
inform the documentation; no implementation was copied. Existing action pins,
minimal permissions, same-run verification, notices and no-overwrite policy remain.
