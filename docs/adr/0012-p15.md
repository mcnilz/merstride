# P15: Hosted Apple Silicon builds and native clean-target qualification

Prepare macOS 15+ Apple Silicon (`osx-arm64`) as a third required release target,
using the standard GitHub-hosted `macos-15` runner and Xcode 16.4. P14's advertised
macOS deferral remains until actual hosted build, extracted-archive and clean-target
evidence passes. Windows/Linux local results cannot establish macOS support.

The managed NUnit host cannot prove execution without an installed .NET runtime.
Publish a separate Native AOT suite driver that parses the same actual Gherkin
sources and runs the same CLI fixture worlds. NUnit uses reflection and dynamic
generic code incompatible with Native AOT; the driver therefore uses a small,
explicit assertion adapter, with negative controls, while NUnit 4 remains the
managed test host. Unsupported constraints fail. Both hosts must pass all runtime
scenarios, including undefined-step failures and exact external child accounting.
No assertions or scenario tags are removed to accommodate macOS.

Use external DTrace process lifecycle events on macOS, including short-lived
successful execs and live ancestry, without substituting process polling. Retain
kernel heartbeats and fail on observation errors, event loss or missing probes.
Run the suite unprivileged; only the observer needs sudo. Keep existing Windows
Job and Linux strace/proc accounting. Hosted trace availability is unverified;
failure blocks the macOS job rather than producing synthetic evidence. Never
disable SIP or relax a product timeout to obtain a pass.

The separate macOS qualification job downloads the same-run archive, fixture and
native driver, removes only approved standalone .NET installation roots on its
disposable hosted VM, and inventories actual runtime absence before executing the
extracted binary and complete runtime suite. PowerShell is an explicitly installed
self-contained interpreter prerequisite; it does not host the suite. Mach-O
architecture, permissions, source/run/version, binary/fixture/driver hashes and
scenario source identities must agree. Keep exhaustive inventories private in job
artifacts. PATH hiding is insufficient. Hosted timings remain separate from
mandatory exact-binary reference-machine budget evidence and the token experiment.

After the initial tag-free hosted verification, run macOS build and clean-target
jobs only in the tag Release workflow to conserve hosted resources. Ordinary
push, pull-request and manual Build runs require Windows and Linux, including
the P15 branch. Release runs bind their actual tagged version and require all
external evidence. Keep the independent clean-target job: a successful build on
an SDK-equipped machine cannot establish execution without system .NET.

Extend the existing aggregate gate, downloads, archive set, checksums, manifests,
qualification validation and immutable draft/publication controls together. No
publication can omit macOS or consume a failed, cancelled, skipped or stale result.
No new action or product dependency is introduced; the official macOS compiler
package's MIT provenance, content hash and complete runtime notices are reviewed.
The native driver is a verification tool and is excluded from product archives.
