# P18 project storage and resource selection

Keep protocol 1, random full resource IDs, saved state schema and engine behavior.
Add convenience at the CLI boundary, without aliases, a current-run pointer,
implicit latest selection, migration or general configuration.

Walk from the calling cwd upward. The nearest directory containing either a
`.merstride` entry or a `.git` entry is the project boundary; `.git` may be a
directory or worktree/submodule pointer file. Never walk beyond that boundary.
Without either marker, use cwd. Default workspace is that boundary; a supplied
absolute `--workspace` overrides only process cwd. Default state root is
`<boundary>/.merstride/runs`; an absolute `--state-dir` overrides only storage.
There are no environment/configuration sources. Workflow paths stay relative to
the caller. Explicit-state callers and existing full IDs keep working.

An existing cwd-relative `.merstride` therefore remains a boundary, even under a
Git parent. Ancestor discovery extends that behavior to subdirectories. A nested
Git project wins over a parent's state. No state is moved, merged or deleted.
Outside a project the first start creates a boundary in cwd. Before first start,
a markerless child directory is independent; users who need a specific parent
should start there or pass explicit storage/workspace paths.

Only successful start preparation creates `.merstride` and appends `/runs/` to
its own `.gitignore` as the final nonempty rule (if needed). Preserve existing bytes and files, including
parent ignore/config content. This local rule ignores persisted state even in a
new project; explicit external roots remain the caller's responsibility. These
are durable runs, never temporary storage. Failed preparation can leave an empty
directory/ignore rule, but never resets saved runs. Concurrent preparation uses
exclusive file access and can fail with I/O error; retry start explicitly.

For status/advance/complete/resolve/logs an omitted run selects only when exactly
one valid full-ID directory exists, including terminal/corrupt/incomplete runs.
Do not filter by status or silently skip broken snapshots. A full ID selects
directly; a prefix `r_` plus 8..32 lowercase hex digits must match exactly one
directory. Missing convenience matches return RUN_NOT_FOUND (4), ambiguity AMBIGUOUS_RUN (4).
Full-ID calls retain their original direct I/O errors (including exit 6 for a
missing full-ID run). Invalid syntax returns INVALID_RUN_ID (4), before using it as a path. Missing
snapshots, corrupt selected state and unusable storage remain exit 6, with no
fallback to another root. Unrelated files/non-ID directories are not runs.

Request selection remains mandatory. Full IDs work unchanged. A `q_` prefix with
8..32 hex digits matches the current request AND all historical receipt IDs,
deduplicated while holding the existing run writer lock. Missing/invalid prefixes
return INVALID_REQUEST (4); ambiguity returns AMBIGUOUS_REQUEST (4). Resolving a
historical prefix feeds its original ID to the existing completion protocol;
equivalent retries return that receipt, conflicts fail, and a newer request stays
untouched. There is no `current`/`latest` request selector to retarget delayed work.

Text summaries retain full IDs and also show eight-hex prefix suggestions. A
suggestion can become ambiguous; lengthen it or use the full ID. JSON responses
keep existing full IDs and fields. Selection is resolved once per invocation;
creating another run later cannot redirect an operation already resolved to a
full ID. Existing locks, interruption/recovery, limits and explicit execution
boundaries remain authoritative. Discovery/help/guides remain state-independent.

Native CLI scenarios cover convenience, collisions, receipts/loops, legacy and
explicit roots, project boundaries, spaces, corruption and ignore preservation.
The unchanged public build boundary covers architecture/policy. New candidate
platform and release qualification remain independently required.
