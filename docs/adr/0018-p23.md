# P23 optional RTK for process commands

Compile the effective YAML boolean into each frozen process node. New workflows
default to enabled. A pre-P23 saved node lacks the boolean and deserializes to
direct execution. Resolve RTK at launch after platform selection. Script forms
keep their existing interpreter and stdin transport.

Use literal process arguments. RTK uses the first argument to dispatch both
filter adapters and its own operations. Use bare names only for vetted adapters
that forward to the same tool, such as `git`, `cargo` and `dotnet`. Pass an
absolute executable path for other commands. Resolving a command and RTK uses
inherited PATH and the selected workspace. When RTK is absent or a bare command
cannot be resolved, the existing direct launch handles the command. Explicit
paths go to RTK as resolved against the workspace. Once the wrapper launch is
attempted, use the normal outcome and limit handling without direct replay.

RTK is caller-provided and optional. No package, shell, version probe, download,
or product installation step is needed. The native acceptance fixtures control
PATH and check both the wrapper invocation and the declared command's effects.
