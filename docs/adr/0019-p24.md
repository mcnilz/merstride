# P24 console-first process output

Send child stdout and stderr to the matching caller streams in text execution.
Keep concurrent byte drains and the shared 10 MiB per-activation pipe budget.
Keep Merstride activity on stderr and summaries on stdout. The same redirected
file descriptor can carry both process bytes and Merstride messages. Each stream
follows its own ordering and backpressure.
Start Merstride messages on a new line when a tool leaves its stream mid-line.
When a limit or interruption expires the drain deadline, abandon a blocked
console write and suppress further messages on that channel for the invocation.
The other channel and the durable route remain available.

Use independent `--save-stdout` and `--save-stderr` switches per execution.
Merstride chooses the existing run-relative activation log filenames. A selected
stream goes exclusively to its file in text; it can supply context tails and
`logs` reads in later commands. The executing snapshot declares the selected
paths before launch. Empty paths denote unsaved output; legacy paths still point
to retained logs. The process marker preserves display classification for new
activations with no paths. Keep all log data outside authoritative state.

For JSON, collect the first 4096 raw bytes of each stream of the last 16 process
activations in memory, with observed sizes, truncation and omission metadata.
Serialize the previews as data within protocol 1. This preserves a single response
frame and adds bounded output even for commands that fail or are handled by a
workflow route. Save switches control file retention independently of previews.
