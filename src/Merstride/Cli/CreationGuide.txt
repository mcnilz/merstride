Merstride workflow creation guide (schema 1, protocol 1)

Create UTF-8 Markdown with one YAML/Mermaid pair per workflow. This guide is
embedded in the native binary: no checkout, content file, runtime or network is
needed. Reading it accesses no workflow/state and executes nothing. For the
execution/completion/recovery loop, use merstride guide --json.
Commands print readable English text by default, including redirected output.
Use --json explicitly for one stable protocol-version-1 object on stdout; guides
then appear in its guide string. Text warnings/errors use stderr, results stdout.
Text advance also reports live activity on stderr: activation (launch pending),
saved process outcomes, numbered Flow #...: source -> destination with exact/default/
unlabeled route reasons, repeated visits, agent waiting and terminal/interrupted states.
This works when redirected; --json suppresses activity. Raw child logs stay separate.
Process exit codes are separate from the overall Result and next caller action.
Waiting/no-route messages explain staying at a node; completion moves the cursor
without execution. Explicit resolution also executes nothing; retry may repeat effects.
Full activation IDs are secondary log selectors, not the human path's identity.

Simple project execution
- merstride start <file> defaults workspace to the nearest ancestor .merstride/.git
  boundary (otherwise cwd), and state to .merstride/runs there. Subdirectories
  share it; nested Git projects stop discovery. No config file or migration.
  Only start adds /runs/ to .merstride/.gitignore, preserving existing content.
- Ordinary start creates and selects a new nonexecuting run; earlier runs are retained.
  Opt in with merstride start <file> --advance to create and first advance in ONE
  native invocation. This may execute multiple nodes until waiting_agent, terminal
  state or error. It targets exactly the created run even if another caller starts.
  After creation, failures keep that ID and saved progress; inspect status/logs
  in its original state root, then recover explicitly. Never automatically repeat
  start or replay effects. Cancellation checked before initial advance leaves
  ready (exit 130); later interruption requires normal explicit resolution.
  Text separates creation from initial advance and final status. Explicit --json
  returns one protocol-1 object with additive start {created, phase, advance};
  other responses have null start. finished means advance returned, not success.
  Update strict response allowlists. No rollback, deletion or measured token claim.
  merstride status and merstride advance use that selection across invocations.
  Use merstride status <file> or merstride advance <file> for another workflow's
  remembered run. complete/resolve/logs share that path-or-run-ID selector.
  Add --workflow <id> for multiple workflows at the same file; quote spaced paths.
  Bare r_ tokens select run IDs; other tokens are source paths, even extensionless.
  Select ID-shaped filenames with ./r_000001 or --file r_000001. --file remains
  an alternative, but cannot be combined with a positional selector. -- ends options.
  runs lists sources/statuses; use <run-id> switches selection deliberately.
  Missing/stale context fails without choosing another run. With no context file,
  legacy exactly-one-run selection remains available, including terminal runs.
- Read and perform the waiting prompt, then merstride complete --request <request-id>
  --outcome <allowed-outcome> and merstride advance. The request remains required:
  its exact ID targets current/historical requests even after current-run changes.
  New run/request IDs have eight characters (r_/q_ plus six hex digits); legacy
  full IDs and unique prefixes still work, with exact identities taking precedence.
  IDs are opaque, predictable, not secrets, and permanently reserved within the root.
  Activation/log IDs remain full. Automation retains exact run/request IDs.
  discard <run-id> deliberately removes only that run, its logs and receipts;
  locked/corrupt/linked/unexpected contents are refused. Start never deletes runs.
  Ambiguity fails; a receipt retry never completes a newer request.
- Absolute --workspace and --state-dir override workspace and storage separately.
  Reuse explicit storage roots; existing cwd-relative state is never moved/deleted.

Pairing and syntax
- Start executable fences at column 1 with at least three backticks; close with
  at least as many. Use the exact info string yaml merstride for metadata and
  mermaid for the graph, containing a whole-line %% merstride: <id> comment.
  The marker and YAML id must match case-sensitively. Block order is irrelevant.
- Ordinary YAML and unmarked Mermaid fences are ignored. Enclosing longer
  backtick or tilde fences hide examples; tilde, indented and container fences
  cannot introduce executable blocks. Reject missing, duplicate or conflicting
  pairs. Omit --workflow only for exactly one pair; otherwise select --workflow <id>.
- IDs (workflow, nodes, outcomes): [a-z][a-z0-9_]{0,63}, case-sensitive.
  Node IDs cannot be end, subgraph, style, class, flowchart, graph or interpolate
  (reserved by Mermaid); workflow IDs may use these names.
- Mermaid header: flowchart TD or flowchart LR. Declare each node explicitly as
  work["Readable label"], with that token contiguous. One declaration or edge per
  line. Use work --> next or work -->|outcome| next. Indentation/whitespace between
  header/edge tokens is allowed; whole-line %% comments and blank lines are allowed.
  Labels cannot contain physical newlines, backslashes, double quotes or HTML;
  Mermaid entities such as #quot; are allowed. Labels are display text, never code.
  No implicit nodes, chained edges, other shapes/arrows, subgraphs, styling,
  click directives, diagram frontmatter or other statements.

YAML schema
- Required root fields: schemaVersion: 1, id, entry, nodes (a mapping by node ID).
  Optional limits: {maxTransitions: 20}; default 100, integer range 1..10000.
  Optional rtk: true or rtk: false; default true for new runs.
  A document is at most 1 MiB; a graph at most 100 nodes and 250 edges.
- Process fields: kind: process, timeoutSeconds (integer 1..3600), and exactly one
  of command/args, script, or variants. command is nonempty; args is an array of
  strings, possibly []. Pass direct arguments literally
  via the OS API: no shell expansion, globbing, interpolation or manual quoting.
  Quote YAML numeric/boolean arguments, e.g. args: ["123", "true", "path with spaces"].
  Bare commands resolve through PATH, relative program paths against the selected
  absolute workspace. Child cwd is that workspace; environment is inherited and
  direct stdin closed. A shell is explicit, e.g. command: pwsh and
  args: [-NoProfile, -NonInteractive, -File, scripts/check.ps1].
- Rust Token Killer (RTK) wraps command/args when enabled and on PATH at advance.
  If unavailable, the command runs directly. Set rtk: false to run directly and
  preserve the command's own output and exit behavior. A process node can override
  the workflow setting with either boolean. Command variants follow this setting.
  Inline script blocks always run directly. Scripts invoked via command follow its setting.
- Inline script: use a multiline literal block (script: |) beginning with a shebang.
  Example node-map fragments (indent beneath the node, retain timeoutSeconds):
    script: |
      #!/usr/bin/env -S python3 -X utf8 -
      print('Shared script: Grüße')
  This needs installed Python 3 named python3 on PATH on every selected platform.
  Bash example (requires installed Bash):
    script: |
      #!bash --noprofile --norc
      printf 'Shared script\n'
  PowerShell/platform example (requires pwsh on Windows and Bash on macOS/Linux):
    variants:
    - platforms: windows
      script: |
        #!pwsh -NoLogo -NoProfile -NonInteractive -Command -
        Write-Output 'Windows'
    - platforms: [macos, linux]
      script: |
        #!bash --noprofile --norc
        printf 'Unix\n'
  variants is a nonempty array; each entry has command/args or script and optional
  platforms (single string or unique nonempty array: windows, macos, linux).
  No condition means all platforms, never fallback. All overlapping conditions
  fail validation, including universal/specific overlap. No match at advance is
  spawn_error with NO_PLATFORM_VARIANT in stderr. Do not mix execution forms.
  Shebang tokens use space/tab and single/double quotes; backslashes are literal,
  without escapes or expansion. Quoted absolute/workspace-relative paths support
  spaces. Bare names search inherited PATH; Windows tries .exe then .com for names
  without extensions. Empty PATH entries are ignored; relative entries use workspace.
  env NAME and env -S NAME ARG... resolve NAME directly without launching env;
  other env options/assignments are unsupported. NAME must be bare.
  The body after the shebang travels as UTF-8 stdin then EOF, without script files.
  Supply flags that execute stdin: no implicit flags or fallback interpreter.
  On Unix, PowerShell -Command - may emit terminal controls. For plain output,
  set TERM=dumb in the environment invoking advance; raw logs stay unchanged.
  YAML normalizes line endings to LF and preserves Unicode/chomping. There is no
  extra interactive/data stdin. Missing interpreter: spawn_error and
  INTERPRETER_UNAVAILABLE in stderr; unlaunchable path: PROCESS_UNAVAILABLE.
  Validation checks syntax only, never launches/downloads/probes interpreters.
  Scripts/variants freeze at start; workspace script files stay live. All existing
  logs, context tails, limits, locks and explicit interruption/recovery rules apply.
  Only already installed interpreters are used; Bash is not an engine prerequisite.
- Agent fields: kind: agent, nonempty prompt (literal string, at most 16 KiB UTF-8),
  optional context (array of unique selectors). Use prompt: | for multiline text.
  Selectors: input; nodes.<id>.exitCode, nodes.<id>.stdoutTail,
  nodes.<id>.stderrTail for process nodes; nodes.<id>.data for agent nodes.
  Save the chosen stream with --save-stdout or --save-stderr on the advance
  that executes the process; otherwise its handoff tail is unavailable.
  Referenced nodes and kinds must be valid. Context is data separate from the
  literal prompt, with no template evaluation. Each selector reads the latest
  completed activation, possibly a previous loop iteration; check availability
  and source activation IDs. Unavailable results are explicit. Stream tails are
  at most 4096 UTF-8 bytes, with truncation/byte counts. Prompt plus serialized
  context must fit 32 KiB; start input and agent data are objects <=16 KiB/depth 16.
- End fields: kind: end, result: success or failure. Both required.
- Only documented fields for each kind are allowed. Required strings must be
  strings, not numbers/booleans/null. Constrained YAML 1.2 core permits string keys,
  strings, booleans, null, finite numbers, sequences, mappings and block strings;
  dates remain strings. Reject unknown fields, duplicate keys, wrong types,
  anchors, aliases, merge keys, explicit/custom tags and multiple documents.
  No includes, object construction, environment expansion or executable expressions.

Graph and routing
- Exactly one YAML definition per Mermaid node and vice versa. Entry must exist;
  every node must be reachable from entry and have a graph path to an end.
  Keep all routing in Mermaid: no YAML edges or next-node fields.
- End nodes have no outgoing edges. Processes have either one unlabeled edge
  (validation warning: it ignores failures) or distinct labeled edges; never mix.
  Normal exits yield exit_<n> (nonnegative n); other outcomes are spawn_error,
  timeout, output_limit and signal. An exact label beats default; no match fails
  with NO_MATCHING_EDGE. Timeout/output-limit termination takes precedence over
  its resulting exit code; first observed limiting cause wins.
- Agent edges are labeled and distinct, with no default. Their labels are the
  complete allowed-outcome set returned to your existing agent. There is no built-in
  LLM. Completion moves only the cursor; advance again explicitly, even for an end.
- Multiple incoming edges are alternative arrivals, never joins. One cursor runs
  sequentially. Cycles need a finite transition budget: each cursor change consumes
  one; an end reached on the last allowed transition may finish. Process output is
  capped at 10 MiB combined per activation; time/output limits attempt tree termination.

Complete example: save the following two fences together as review.md.
Running its process requires Git installed on PATH and a Git workspace; guide
retrieval and validation require neither. Git arguments below are literal strings.

```yaml merstride
schemaVersion: 1
id: review
entry: check
limits:
  maxTransitions: 20
nodes:
  check:
    kind: process
    command: git
    args: [diff, --check]
    timeoutSeconds: 60
  review:
    kind: agent
    prompt: |
      Inspect the workspace changes with your existing tools.
      Return approved if they are acceptable, otherwise rejected.
    context: [nodes.check.exitCode, nodes.check.stdoutTail, nodes.check.stderrTail]
  done:
    kind: end
    result: success
  failed:
    kind: end
    result: failure
```
```mermaid
flowchart TD
    %% merstride: review
    check["Check whitespace errors"]
    review["Review changes"]
    done["Accepted"]
    failed["Needs work"]
    check -->|exit_0| review
    check -->|default| failed
    review -->|approved| done
    review -->|rejected| failed
```

Authoring checklist
1. Match workflow IDs, fences, node IDs and the existing entry.
2. Use only the supported YAML fields/Mermaid forms, literal string arguments and
   valid selectors. Check interpreter/program prerequisites before execution.
3. Check reachability, paths to ends, explicit failure routes and transition budget.
4. Save UTF-8 and validate; validation launches/downloads nothing and creates no run.
   For multiple pairs add --workflow <id>. Finish with:
   merstride validate <file> --json
